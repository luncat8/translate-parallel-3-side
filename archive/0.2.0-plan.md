# 0.2.0 — song-folder architecture

## Goal

Make the project reusable for any number of songs without editing build scripts or absolute paths. A song is a self-contained unit with sources, expected translations, a canonical map and a generated standalone HTML result.

## Invariants

- One shared engine in `engine/`; never copy or fork it per song.
- `songs/<id>/song.json` is the only place that names a song's files. All paths are relative to that folder.
- `sources/source.ja.txt` is the fixation with stanza gaps. `fixation.json` is its nonblank line list.
- Every aligned text file — Romaji and expected translations — has one line per source line and the same blank-line positions.
- `map/song-data.js` uses the canonical `META` + `DATA` model; source key `jp`, mirror key `tr`, target keys `en` and `ru`.
- `result.html` is deterministic output of the engine template, the map and the manifest title. It is never hand-edited.
- ERROR-level validator issues fail the build. `check` also verifies alignment and result freshness.

## Workflow

1. `tools/song.py new` scaffolds a folder from a TSV source and optional line-aligned Russian expected translation.
2. `fixation` regenerates ground truth from the plain source.
3. `starter-map` creates a line-level preview map from aligned expected translations. A linguist replaces it with a word-level map.
4. `export` derives expected translations from a finished word-level map.
5. `build --all` injects each map into the engine, writes `result.html` and gates on Node validation.
6. `check --all` verifies layout, alignment, deterministic output and validation.

## Deliverables

- Two example song folders: one hand-segmented word map and one expected-translation starter example.
- A single CLI, a Makefile, regression tests and documentation describing the contract.
- The built `result.html` files are committed because each song must ship with its result.

## Acceptance

- `make check` passes with zero errors.
- Both songs have identical folder shape and independently buildable results.
- Adding a third song requires no changes under `engine/` or `tools/`.
