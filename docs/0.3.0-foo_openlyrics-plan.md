# 0.3.0 — multilingual word-map bundle for foo_openlyrics

## Goal

Store many languages with the existing colorization schema, then render them inside
foobar2000: one block per lyric line, languages stacked under the original, each word
coloured by part of speech, and the cursor (the time position) lighting up the same
meaning in every language at once.

This document is the contract between two repositories:

| Repo | Role |
|---|---|
| `translate-parallel-3-side` (this repo, "LinguaMap") | owns the data model, the colour schema, the validators and the exporter |
| fork of [`jacquesh/foo_openlyrics`](https://github.com/jacquesh/foo_openlyrics) ("the fork") | owns retrieval, layout, scrolling, hit-testing and preferences |

The fork does not re-implement map authoring. It consumes one text artefact produced
here, and it must be able to reject it loudly instead of showing something wrong.

Both repos are MIT; the lyrics are not. The fork ships no lyric text of its own.

## Non-goals

- No new authoring UI in foobar2000. Segmentation stays a text-editing job in this repo.
- No network source for maps. This release reads local files only; adding a remote map
  source is a later subject.
- No change to word-level authoring rules (`AGENTS.md` stays the authority).
- No second colour schema. The fork renders exactly the POS codes defined here.
- No LRC `[lang:]` tagging of physical lines. Nesting inside one timed line is the point.

## Target layout

For a track with a map, one block per timed line — the user's requested layout:

```
[00:12.40]                               ← time mark for the block below
夕暮れ　空を見上げ                          ← original (source column, byte-exact)
	yuugure sora o miage                 ← transcription/transliteration (JP only)
	В сумерках смотрим вверх на небо —    ← translation 1
	At dusk, gazing up at the sky —      ← translation 2
                                         ← blank line separates blocks
[00:16.10]
みんなで手を伸ばしてみよう
	minna de te o nobashite miyou
	Все вместе попробуем вытянуть руки —
	All together, let's try reaching our hands out —
```

On screen the timestamp is a gutter element, not text in the block:

```
 00:12.40 │ 夕暮れ　空を見上げ
          │ yuugure sora o miage
          │ В сумерках смотрим вверх на небо —
          │ At dusk, gazing up at the sky —
```

Rules:

- The timestamp sits on its own physical line so the source line stays byte-exact; the
  renderer draws it as a dim gutter, and the timed (highlighted) line is the source line
  plus every continuation line of its block.
- Column lines are indented; the source is never indented, so no continuation can be
  mistaken for a new block and no block can be mistaken for a continuation.
- Column order is data, not code: `source, transliteration?, translations…`; translations
  keep their `META.columns` order.
- Transliteration appears only when the map has one (`@translit`) and the source is not
  already Latin; the plan makes it a config, not an assumption about Japanese.
- A blank line separates blocks; the reader ignores blank lines and never treats one as a
  block. One block = one source line + its column lines, nothing else.
- Untimed maps are allowed and fall back to the plain lyric view with the same columns and
  colours, just no cursor.

## Wire format: `*.lmz.txt`

One file per line-oriented text: UTF-8 (BOM tolerated on read), LF or CRLF. By default it
is the lyric sidecar of a track, `<lyrics-dir>/<Artist> - <Title>.lmz.txt` (see
§Fork·retrieval). A working example lives in `docs/examples/jumping-girl.lmz.txt` — all 53
blocks of an existing song, exported from its map, byte-exact on the source column.

```
#!linguamap 1
# '#' comments are ignored anywhere; blank lines are cosmetic.
@title        Jumping girl
@source       jp
@translit     tr
@columns      jp,tr,ru,en
@columnTitles ru=Русский,en=English,jp=日本語,tr=Romaji
@pos          n=#1a5fc4,npr=#3240a8,v=#c22b35,adj=#1e7c34,adjna=#647c11,adv=#7c2cae,pron=#0a7a80,conj=#bc5a10,interj=#b13272,part=#77705f,q=#93700a
@posDark      n=#7fb2f0,npr=#94a2f0,v=#f28b8b,adj=#82d18d,adjna=#c6d46e,adv=#cb9ee0,pron=#6fcbcd,conj=#f0a763,interj=#f099c4,part=#aab2bc,q=#e6c35f
@timeFormat   lrc
@offset       0
@credit       short credit line shown in the diagnostics dialog

[00:12.40]
夕暮れ　空を見上げ
	yuugure sora o miage
	В сумерках смотрим вверх на небо —
	At dusk, gazing up at the sky —
[00:16.10]
みんなで手を伸ばしてみよう
	minna de te o nobashite miyou
	Все вместе попробуем вытянуть руки —
	All together, let's try reaching our hands out —
```

Grammar (normative — `engine/parse_linguamap.js` is the executable version):

- `#!linguamap 1` must be byte 0 (after an optional UTF-8 BOM). Anything else is not a
  bundle, including an LRC file that happens to start with a similar tag.
- `#` starts a comment; the rest of the line is ignored. There are no other escapes.
- `@key value` headers. **One header per physical line — no continuations** (a `@pos`
  line is short enough; wrapping it was a needless parsing hazard). Text after `value`
  on the same line is part of the value except trailing whitespace. A key may not repeat.
- Header values: `,` separates list items, `=` separates key from value (first `=` wins),
  `|` separates languages, and nothing else is special. Keys are compared exactly.
- Required: `@columns`, `@source`, `@timeFormat`. Optional: `@translit`, `@columnTitles`,
  `@pos`, `@posDark`, `@offset`, `@credit`, `@glossary`, `@title`.
- `@timeFormat lrc` uses `[mm:ss.cc]` / `[h:mm:ss.cc]`, exactly what
  `parsers::lrc::print_timestamp` writes (2-digit centiseconds). `@timeFormat none` means
  untimed: `[`-lines are then source text and must not be parsed as stamps.
- A block is one source line plus the column lines that follow it. The source line is the
  first line that is neither a header, a comment, a timestamp, nor indented. Every
  non-header, non-comment, non-timestamp line that starts with TAB or two spaces is a
  column line of the current block, in `@columns` order minus the source. Text that begins
  with `@` on a column line is still column text, not a header.
- Timestamp lines keep only the stamp: `[00:12.40]` alone on the line. (Tolerated on read,
  for files produced by the existing LRC exporters, is `[00:12.40]<text>`, where the text
  must be the block's source verbatim; it is parsed and discarded. `print_timestamp` stays
  the only writer of the stamp, so nothing else can drift.)
- Column position is stable: an empty cell is a line containing only the indent
  (one TAB, nothing else), never a missing line. Fewer column lines than expected is a
  hard error for that block, never a silent shift.
- The exporter writes TAB indent; the reader accepts TAB or exactly two spaces.
- `@offset` (seconds, may be negative) is added to every timestamp, for lining a bundle
  up with a differently-timed copy of the same recording.
- A `#!linguamap` version other than `1` is refused whole with a "newer LinguaMap" message.

## The colour schema

Colour **is** grammar. There is exactly one palette, defined once in
`engine/colorization.json` (extracted from the template CSS, verified equal by a test) and
copied verbatim into every bundle. The fork never invents colours: on load it takes
`@pos`/`@posDark` from the file; when they are absent it falls back to a compiled-in copy
of the same table, and a mismatch with the built-in table is a diagnostics warning.

| code | class | light | dark |
|---|---|---|---|
| `n` | noun | `#1a5fc4` | `#7fb2f0` |
| `npr` | proper noun | `#3240a8` | `#94a2f0` |
| `v` | verb | `#c22b35` | `#f28b8b` |
| `adj` | i-adjective | `#1e7c34` | `#82d18d` |
| `adjna` | na-adjective | `#647c11` | `#c6d46e` |
| `adv` | adverb | `#7c2cae` | `#cb9ee0` |
| `pron` | pronoun | `#0a7a80` | `#6fcbcd` |
| `conj` | conjunction | `#bc5a10` | `#f0a763` |
| `interj` | interjection | `#b13272` | `#f099c4` |
| `part` | particle | `#77705f` | `#aab2bc` |
| `q` | question word | `#93700a` | `#e6c35f` |

Rules for renderers:

- Colour by the POS of the **source head**, per unit, in every column. Never recolour by
  the target language's own grammar — that would erase the parallel signal.
- Within one line the same `name` gets the same colour in every column; that is what makes
  the parallel reading work at a glance.
- `pos` missing from the palette ⇒ render in the main text colour and report it once per
  file in diagnostics. An unknown code is a warning, not a crash: maps outlive versions.
- The source-language grammar decides all colours. `part` is only for languages that leave
  particles unwrapped; for a language set without that class, the code is simply unused.
- Dark mode swaps the table in place (`@posDark`), no reload, no re-parse.
- Accessibility: the palette pairs are chosen for ≥4.5:1 contrast on the panel background
  in both themes; the fork's active-block highlight must not reduce that contrast below
  the threshold — that is why the highlight is a background, not a colour change (§cursor).

## Cursor semantics ("cursor highlight parallel places")

The cursor is the playback position projected onto one **block**:

1. The active block is the last block whose timestamp ≤ `current_time + offset`.
2. The active block is highlighted as a whole — all columns together — with the existing
   highlight colour as a **background tint plus a left rule**, while every unit keeps its
   POS colour. Painting the text in the highlight colour instead would destroy the
   grammar colours exactly where the eye is; that is rejected on purpose.
3. Optional next-block pre-highlight fades in over `highlight_fade_seconds`, reusing the
   existing scroll curve so the map scrolls exactly like the plain lyric panel.
4. Hovering a word dims every unit except the ones sharing its `name` (all lines, all
   columns) — the same interaction the HTML engine offers with `highlight(name)`.
5. Clicking a word seeks to that block's timestamp minus `@offset`.
6. Scrolling the panel past the active block gives the user a peek; the next timer tick
   snaps back (same behaviour as the plain panel's manual scroll reset).

Celeration/karaoke timing is out of scope: one cursor, one block, one transition.

## Repo 1 — LinguaMap (this repo)

### P0.1 map languages are data, not code

- `META.columns` already drives the HTML grid (`--cols` is set from it in `applyCols`), so
  an arbitrary language count needs no CSS change. Audit and keep
  `repeat(var(--cols,4),minmax(0,1fr))`.
- Fix the one real inconsistency found in the audit: the CSS palette declares `q` before
  `part`, while `META.posOrder` lists `part` before `q`. Harmless today, fatal for a
  generated table — `colorization.json` is keyed by code, and a test asserts template CSS
  == JSON == `META.posOrder` set.
- Add per-language metadata: `META.columnTitles` (exists), `META.translit` (new,
  `{ja: "tr"}`), `META.dir` (new, `{ar: "rtl"}`, CSS rule only).
- Accept a source language other than `ja`: `tools/song.py new --source-lang <tag>` and
  `sources/source.<tag>.txt`. Keep `jp` as the default source key so existing maps and
  `result.html` files do not move.

### P0.2 one palette, two consumers

- `engine/colorization.json` is now the single source of truth (written: 11 codes × light
  and dark, `schema: "linguamap-colorization"`).
- `tools/song.py build` injects the table into the template (replacing the hard-coded CSS
  block) and exposes it as `META.posColors`, so the legend and the page use one table.
- `tools/song.py palette --json` prints it; that output is what the fork copies into
  `src/colorization.h`. A test asserts the JSON, the template CSS and `META.posOrder`
  describe the same 11 codes.

### P0.3 language sets beyond en+ru

- `songs/<id>/song.json`: `expectedTranslations` becomes an ordered map of any length;
  `columns` is derived as `[source, translit?] + translations` unless set explicitly.
- `tools/song.py new` takes repeatable `--expected <lang>=<path>`; `--expected-ru` and
  `--expected-en` stay as aliases so existing commands and `tests/` keep working.
- `engine/export_translations.js` already walks `META.columns` minus source/translit;
  extend it to emit `expected-translation.<lang>.txt` for every such column.
- The starter map fills **every** language cell, so a `ja/tr/en/ru/de` map renders today
  with no engine change.

### P0.4 the canonical bundle exporter

- New `engine/export_linguamap.js`: `song-data.js` → `<id>.lmz.txt` (+ `--check`).
  - Writes every header, palette included; one header per line (see §grammar).
  - `section` / `gap` / `title` blocks become separators only, so timed blocks == lines.
  - Column order = `@columns`, always source first, then translit (if
    `META.trMirror !== false`), then translations in `META.columns` order minus those two.
    The source is never a column line — it is the block's own first line.
  - Translation cells honour `ord[lang]`; internal whitespace collapses to single spaces.
    The **source** cell is `block.src`, byte-exact, never normalised.
  - Output is byte-stable: same map ⇒ same file, so `check` can diff it.
- New `engine/parse_linguamap.js`: the reference **reader**, returning
  `{meta, blocks, warnings, errors}`. Pure, dependency-free, Node-runnable. This is the
  executable specification the fork ports tests from.
- `tools/song.py bundle --song <id>` writes `songs/<id>/export/<id>.lmz.txt`;
  `check` re-parses it with the reader and diffs against the map (source bytes, per-column
  text, palette, timestamps), and fails when the committed export is stale.

### P0.5 timestamps in the map

The map has no timing today. Add one optional field per line block:

```js
{ type: "line", t: 12.40, src: "夕暮れ　空を見上げ", units: [ … ] }
```

- `t` is seconds (float) or `"mm:ss.cc"`. Values must be strictly increasing; duplicates
  and regressions are validation errors.
- Untimed maps omit `t` everywhere; mixing timed and untimed lines is an error.
- New `tools/song.py timestamps --song <id> --lrc <file.lrc>` seeds `t` by matching source
  line text in order and reports every unmatched line. Timing is authored in the fork's
  LRC editor (existing `[stamp]` button) and imported here; this repo never guesses times.
- Round-trip: `bundle` writes `@timeFormat lrc`, and `bundle --check` proves the bundle's
  timestamps equal the ones in the map.

### P0.6 gold text stays golden

- `export/` is derived output, committed like `result.html`; `check` fails if stale.
- `AGENTS.md` gets a short bundle section; `songs/README.md` lists the new files;
  `archive/0.3.0-worklog.md` records decisions and the validation log.
- Tests: reader round-trip, palette equality (JSON/CSS/posOrder), N-language fixture
  (`ja/tr/en/ru/de`), timestamp monotonicity, stale-export detection, comment handling,

### P0.7 sample data for the fork

```cpp
enum pos_code : uint8_t { POS_N, POS_NPR, POS_V, POS_ADJ, POS_ADJNA, POS_ADV,
                          POS_PRON, POS_CONJ, POS_INTERJ, POS_PART, POS_Q,
                          POS_COUNT, POS_UNKNOWN = 0xFF };

struct UnitSpan { std::string text; uint8_t pos; };  // 'name' only if hover needs it

struct MapColumn { std::string language, title; std::vector<UnitSpan> units; };

struct MapLine
{
    double timestamp;              // DBL_MAX when untimed
    std::string source;            // byte-exact, for plain-lyrics parity
    std::vector<MapColumn> columns; // in @columns order, source omitted
};

struct LyricMap
{
    int format_version = 0;
    std::vector<std::string> column_languages;   // @columns
    std::array<COLORREF, POS_COUNT> pos_light{};
    std::array<COLORREF, POS_COUNT> pos_dark{};
    bool palette_from_file = false;              // false ⇒ built-in table used
    std::string title, credit;
    double offset = 0.0;
    std::vector<MapLine> lines;
    std::map<std::string, std::string> glossary; // name -> "ru|en" for diagnostics
};
```

### Fork·parser

`parsers::linguamap::parse(std::string_view utf8) -> MapParseResult`
(`{std::optional<LyricMap> map; std::string error; int error_line;}`):

- Hand-written, allocation-light, no exceptions on the happy path; reuse
  `parsers::lrc::try_parse_timestamp` / `print_timestamp` so time grammar is shared.
- Validation order (first error wins): magic → version → headers (`@columns`, `@source`,
  `@timeFormat` present; no duplicate keys) → palette (`#rrggbb`, known codes; unknown code
  ⇒ warning, unparsable hex ⇒ error) → blocks (indent count == expected columns) →
  timestamps (strictly increasing, `@offset` applied) → non-empty.
- Build `LyricData.lines` in the same pass: one entry per block, `text = source`, with the
  block separators preserved as the plain view expects. Map on/off then changes only
  colours and columns, never which line highlights when.
- MVTF tests in `src/maptest.cpp` (runs under the existing `test_foo_openlyrics.exe`):
  accept path (golden fixture), LF and CRLF, BOM, comments anywhere, empty cell, one
  block, five columns, untimed file, `@offset` sign, and one test per rejection case.

### Fork·retrieval from local files

`class LinguamapFileSource : public LyricSourceBase` in `src/sources/linguamapfile.cpp`
(modelled line-for-line on `LocalFileSource`):

- `is_local() = true`, `is_dummy() = false`, `friendly_name() = "LinguaMap files"`,
  fresh `GUID` via `guidgen` (record it in `docs/linguamap.md`; never change it).
- Path: `preferences::saving::filename(track, track_info) + ".lmz.txt"`, so the existing
  *filename format* and *lyrics directory* settings govern bundles too, and
  `Artist - Title.lmz.txt` sits next to `Artist - Title.lrc`.
- `search()` returns a candidate when the file exists; `lookup()` reads with
  `filesystem::g_open_read` + `read_till_eof` (as `LocalFileSource::lookup` does, which is
  the upstream fix for UTF-16-ish byte streams).
- **Priority**: add the source to the default active list *before* `LocalFileSource`, since
  `internal_search_for_lyrics` returns the first usable hit. Help text on the preferences
  page states: "a .lmz.txt bundle wins over a .lrc for the same track". No new priority
  mechanism, no per-source weighting.
- Case-SmartFileSystem: `g_exists` is case-insensitive on Windows; do not lower-case paths
  ourselves, and do not enumerate directories (one lookup, no scan).

### Fork·rendering

`DrawTimestampedLyrics` (GDI) currently loops `m_lyrics.lines` and calls
`DrawWrappedLyricLine`, which wraps at whitespace with `GetTextExtentPoint32`. Keep that
shape and swap the inner unit of work:

- New `DrawMappedLyrics(HDC, CRect)`, entered from `DrawTimestampedLyrics` when
  `m_lyrics.map && preferences::display::map_enabled()`. Untimed bundles go through
  `DrawUntimedLyrics` with the same column renderer and no cursor.
- Shared layout helper (one implementation, two windows):
  `int DrawMapBlock(HDC, CRect, const MapLine&, CPoint origin, const MapPalette&, BlockStyle)`
  returns the block height. It walks columns, and for each column draws unit runs
  (`SetTextColor(pos_colour); TextOut(...)`) with the existing wrap loop; wrapped
  continuation lines get `indent_px = (2 * tmHeight) / 3`.
- Block height = sum of column heights + `linegap()` between columns. Compute with the
  same function (a `draw = false` path) *before* painting, so scrolling never jumps.
- Skip `pos` codes the palette lacks by drawing in `main_text_colour` — never a gap.
- Empty cells (columns that are absent for one line) simply contribute nothing; vertical
  rhythm stays per-block, not per-column, so nothing misaligns.
- External window: the same helper, but Direct2D — `IDWriteTextLayout` per column with
  per-run `SetDrawingEffect` (or one `DrawTextLayout` per run); shares
  `DrawMapBlock`'s geometry decisions, duplicates only the draw calls.
- Column visibility (`preferences::display::map_visible_columns`) filters columns before
  layout, so hiding the transliteration reflows heights correctly.

### Fork·cursor and interaction

- Reuse `get_scroll_position`: `active_line_index` is the block index because plain lines
  and map blocks are one-to-one. No second time model.
- Active block: background tint from `hl_colour` at ~18% alpha behind the whole block, plus
  a 3 px left rule; unit colours unchanged. The next block's tint fades in with
  `highlight_fade_seconds`, matching the existing text fade.
- Past blocks: blend each POS colour 35% toward `past_text_colour` (preference). Future
  blocks: full palette colour. This keeps grammar readable while scrolling.
- Hover: `OnMouseMove` (already handled) gains a hit test over the block rectangles
  recorded during the last draw. Hovered unit's `name` ⇒ dim all other units in the panel
  to the panel's `past_text_colour` (or 30% opacity via a lighter blend), restore on leave.
  Hover is disabled while `m_manual_scroll_start` is set, so dragging still scrolls.
- Click: `OnLMBDown`→`OnLMBUp` with < 4 px movement and a unit under the cursor ⇒
  `playback_control::playback_seek(block.timestamp - timestamp_offset)`. A click that
  followed a drag never seeks. Double-click still opens the editor (upstream behaviour).
- Keyboard: if `Ctrl+Up/Down` is free in the panel, jump a block; otherwise skip — not
  worth a conflict with the host.
- One repaint per timer tick, no extra timers; the existing 16 ms timer is enough.

## Compatibility

- `song.json` and `map/song-data.js` stay valid: `t`, `columnTitles`, `posColors` and extra
  columns are additive. Old maps export a `#!linguamap 1` bundle with `@timeFormat none`.
- A bundle whose magic version is not `1` is refused whole ("produced by a newer
  LinguaMap"), never partially parsed.
- Unknown `@keys` and unknown POS codes are warnings, not errors: a v1 reader must survive
  a v1.x writer adding optional data. Structural problems are always errors.
- Existing tools/tests stay green at every step: `make check` gates Repo 1; `msbuild` plus
  `test_foo_openlyrics.exe` gates the fork. Neither may be "temporarily red".
- The bundle is one file with culture-independent line structure: no locale-dependent
  number formatting (use `%.2f` / integer centiseconds), no OS-dependent newlines on write.

## Risks

| Risk | Mitigation |
|---|---|
| Two implementations of the format drift | the Node reader is the spec; the fork ports its *tests*, not its behaviour, and the golden fixture is shared |
| Column layout is expensive to draw at 60 fps | draw columns as runs, cache per-block layout in `map` on first draw, invalidate on width/font/preference change |
| Wrapped columns make block heights jump | compute heights with the same function used for drawing before the first paint of a block; never estimate |
| Bundle out of sync with the map | `bundle` is generated output, `check` compares it, CI-style gate in `make check` |
| Hover + manual scroll fight each other | hover only when no mouse button is down; manual scroll keeps today's semantics |
| Direct2D path lags the GDI path | same data + same height functions; ship GDI first, Direct2D second, both gated by the same flag |
